# 통계 분석 (카이제곱, F-검정) 및 Python 활용 가이드

이 문서는 데이터 분석에 사용되는 주요 통계 기법인 **카이제곱 검정(Chi-squared Test)**과 **F-검정(ANOVA)**의 개념을 설명하고, `chi2_category_data.py`와 `arona_f_stats.py` 예제 코드를 통해 Python으로 각 분석을 수행하는 방법을 안내합니다.

## 1. 어떤 분석을 선택해야 할까? (카이제곱 vs. F-검정)

데이터를 분석할 때는 변수의 유형에 따라 적절한 통계 기법을 선택해야 합니다.

| 분석 대상 | 변수 1 (독립변수) | 변수 2 (종속변수) | 주요 질문 | 대표 검정 |
| :--- | :--- | :--- | :--- | :--- |
| **연관성** 분석 | 범주형 | 범주형 | 두 변수가 서로 관련이 있는가? | **카이제곱 검정** |
| **평균 차이** 분석 | 범주형 | 연속형 | 그룹 간 평균에 차이가 있는가? | **F-검정 (분산분석)** |

-   **카이제곱 검정 (Chi-squared Test)**: **`범주형 변수`**와 **`범주형 변수`**의 연관성을 분석합니다.
    -   **예시**: "할인율 **그룹**"과 "평점 **그룹**" 간의 관계처럼, 두 변수 모두 그룹화된 경우 각 조합의 **빈도(횟수)**를 기반으로 연관성을 검정합니다.

-   **F-검정 (F-test, 분산분석/ANOVA)**: **`범주형 변수`**에 따른 **`연속형 변수`**의 **평균** 차이를 분석합니다.
    -   **예시**: "할인율 그룹(0~20%, 20~40% 등)"에 따라 실제 "평점(1.0~5.0점)"의 **평균**이 통계적으로 유의미하게 다른지 검정하고 싶을 때 사용합니다.

## 2. 가설 검정의 핵심 개념

통계적 가설 검정은 데이터를 통해 어떤 주장이 맞는지 아닌지를 판단하는 과정입니다. 이 과정의 핵심 요소는 귀무가설, p-value, 유의수준입니다.

### 2-1. 귀무가설(H₀)과 대립가설(H₁)

-   **귀무가설 (Null Hypothesis, H₀)**
    -   **정의**: 통계적으로 검정하려는 "기본 가설" 또는 "차이가 없다/효과가 없다/관계가 없다"는 주장입니다. 분석의 목표는 이 귀무가설이 틀렸다는 증거를 찾는 것입니다.
    -   **예시 (우리 프로젝트)**:
        -   (카이제곱 검정) "할인율과 평점 사이에는 **연관성이 없다**."
        -   (F-검정) "모든 할인율 그룹 간 평점 **평균은 동일하다**."

-   **대립가설 (Alternative Hypothesis, H₁)**
    -   **정의**: 귀무가설이 기각될 경우 대안으로 채택되는 가설입니다. "차이가 있다/효과가 있다/관계가 있다"는 주장을 담고 있으며, 분석가가 입증하고자 하는 내용인 경우가 많습니다.
    -   **예시 (우리 프로젝트)**:
        -   (카이제곱 검정) "할인율과 평점 사이에는 **연관성이 있다**."
        -   (F-검정) "적어도 하나의 할인율 그룹의 평점 **평균은 다르다**."

### 2-2. p-value와 유의수준(α)을 이용한 분석

-   **p-value (유의 확률)**
    -   **정의**: **귀무가설(H₀)이 참이라고 가정했을 때**, 현재 관측된 데이터와 같거나 더 극단적인 결과가 나올 **확률**입니다.
    -   p-value가 낮을수록 "귀무가설이 맞다고 치니 이런 결과가 나올 확률이 너무 낮네? 귀무가설이 틀린 것 같다"고 생각할 수 있습니다.

-   **유의수준 (Significance Level, α)**
    -   **정의**: "이것보다 낮은 확률의 사건은 우연으로 보지 않겠다"고 정하는 **기준선(임계 확률)**입니다. 분석가가 직접 설정하며, 보통 **0.05 (5%)**를 가장 많이 사용합니다.
    -   α=0.05는 5%의 '위험'을 감수하겠다는 의미입니다. 즉, 실제로는 귀무가설이 맞는데도 우연히 희귀한 데이터가 나와 귀무가설을 기각할 오류(1종 오류)를 5%까지 허용하겠다는 뜻입니다.

-   **판단 규칙 (Decision Rule)**
    -   **`p-value < α`** (예: `p < 0.05`): 결과가 **통계적으로 유의미하다**.
        -   **결정**: **귀무가설을 기각한다.**
        -   **결론**: 대립가설을 채택한다. (예: "그룹 간 평균에 차이가 있다.")
    -   **`p-value ≥ α`** (예: `p ≥ 0.05`): 결과가 통계적으로 유의미하지 않다.
        -   **결정**: **귀무가설을 기각하지 못한다.** (귀무가설이 '맞다'고 증명된 것은 아님)
        -   **결론**: "그룹 간 평균에 차이가 있다고 말할 통계적 근거가 부족하다."

### 2-3. 왜 p-value를 사용할까? (임계값 방식 vs p-value 방식)

스크립트의 `critical_value`는 **임계값(Critical Value) 방식**을 보여주기 위한 교육용 예제입니다.

-   **임계값 방식**: 정해진 유의수준(α)에 해당하는 통계량(카이제곱 값, F 값 등)의 커트라인을 미리 구해놓고, 내가 계산한 통계량이 이 커트라인을 넘는지 아닌지만 확인합니다.
-   **p-value 방식**: 계산된 통계량에 해당하는 확률(p-value)을 직접 구해 유의수준(α)과 비교합니다.

오늘날 p-value 방식이 더 선호되는 이유는 다음과 같습니다.
1.  **더 많은 정보 제공**: p-value는 결과가 '얼마나' 유의미한지를 알려줍니다. p-value 0.04와 0.0001은 둘 다 유의하지만, 후자가 훨씬 더 강력한 증거입니다.
2.  **유연한 해석**: 결과를 보는 사람이 각자의 유의수준(0.05, 0.01 등)을 기준으로 자유롭게 판단할 수 있습니다.

따라서 최신 통계 소프트웨어는 모두 p-value를 기본으로 제공하며, 이를 해석하는 것이 표준적인 분석 방법입니다.

## 3. 코드 예제 및 해석

### 3-1. 카이제곱 검정 (`chi2_category_data.py`)

**`목표`**: 상품의 '할인율 그룹'과 '평점 그룹'이라는 두 범주형 변수 간에 통계적으로 유의미한 연관성이 있는지 확인합니다.

**`주요 로직`**:
1.  `pandas.cut()`: 연속형 데이터인 '할인율'과 '평점'을 각각의 그룹으로 나누어 범주화합니다.
2.  `pandas.crosstab()`: 두 범주형 변수를 기준으로 교차표(빈도표)를 생성합니다.
3.  `scipy.stats.chi2_contingency()`: 생성된 교차표를 기반으로 카이제곱 검정을 수행합니다.

**`코드`**:
```python
# 1. 연속형 데이터를 범주형으로 변환
df['rating_group'] = pd.cut(...)
df['discount_percentage_group'] = pd.cut(...)

# 2. 교차표 생성
pivot_df = pd.crosstab(df['discount_percentage_group'], df['rating_group'])

# 3. 카이제곱 검정 수행
chi2, p_value, _, _ = chi2_contingency(pivot_df)
```

**`결과 및 해석`**:
-   `chi2` (통계량): 29.925
-   `p_value`: 0.000217
-   `p-value`(0.000217)가 유의수준 0.05보다 매우 작으므로, 귀무가설("두 변수는 연관성이 없다")을 기각합니다.
-   **결론**: 상품의 할인율과 평점 사이에는 **통계적으로 유의미한 연관성이 존재합니다.**

### 3-2. F-검정 / 분산분석 (ANOVA) (`arona_f_stats.py`)

**`목표`**: '할인율 그룹'에 따라 상품의 **평균 평점**에 통계적으로 유의미한 차이가 있는지 확인합니다.

**`주요 로직`**:
1.  `pandas.cut()`: 연속형 데이터 '할인율'을 그룹으로 나누어 범주화합니다.
2.  `DataFrame.groupby()`: '할인율 그룹'으로 데이터를 묶습니다.
3.  `scipy.stats.f_oneway()`: 각 그룹에 속한 평점 데이터들을 인자로 받아 분산분석을 수행합니다.

**`코드`**:
```python
# 1. 할인율 그룹으로 그룹화
# 각 그룹에 속한 'rating' 값들의 배열을 리스트로 생성
discount_groups = [group["rating"].values for name, group in df.groupby("discount_percentage_group")]

# 2. F-검정 수행
# *discount_groups는 리스트의 각 항목(배열)을 개별 인자로 전달
f_stat, p_value = stats.f_oneway(*discount_groups)
```

**`결과 및 해석`**:
-   `f_stat` (F-통계량): 7.475
-   `p_value`: 5.849e-06
-   `p-value`(0.0000058)가 유의수준 0.05보다 매우 작으므로, 귀무가설("모든 그룹의 평균은 동일하다")을 기각합니다.
-   **결론**: 할인율 그룹에 따라 상품의 **평균 평점에는 통계적으로 유의미한 차이가 존재합니다.**

## 4. 핵심 Python 문법

-   **`scipy.stats.chi2_contingency(observed)`**: 분할표(교차표)를 입력받아 카이제곱 검정을 수행하고 통계량, p-value 등을 반환합니다.
-   **`scipy.stats.f_oneway(*args)`**: 두 개 이상의 독립적인 그룹(배열)을 인자로 받아 일원분산분석(ANOVA)을 수행하고 F-통계량과 p-value를 반환합니다.
-   **`pandas.cut(x, bins, labels)`**: 연속형 데이터를 지정된 구간(`bins`)으로 나누어 범주화합니다.
-   **`pandas.crosstab(index, columns)`**: 두 변수를 기준으로 교차표(빈도표)를 생성합니다.

## 부록: Python 제네릭 (Generics) 이란?

제네릭은 **타입을 파라미터화**하여, 다양한 데이터 타입에서 작동하는 재사용 가능한 함수나 클래스를 만들 수 있게 해주는 기능입니다. 이를 통해 코드의 유연성과 타입 안정성을 동시에 높일 수 있습니다.

### 왜 사용하나요?

-   **타입 안정성 (Type Safety)**: 함수나 클래스가 처리할 수 있는 타입과 반환하는 타입 간의 관계를 명확히 하여, `mypy`와 같은 정적 타입 검사기가 잠재적인 오류를 컴파일 전에 찾아낼 수 있도록 돕습니다.
-   **코드 재사용성 (Reusability)**: `int`, `str` 등 특정 타입에 종속되지 않는 범용적인 컴포넌트를 작성할 수 있습니다.
-   **가독성 및 명확성**: 코드만 봐도 어떤 타입이 입력되고 어떤 타입이 반환될지 명확하게 이해할 수 있습니다.

### 기본 사용법: `TypeVar`

`TypeVar`는 제네릭 타입을 생성하는 가장 기본적인 방법입니다.

```python
from typing import TypeVar, List

# 'T'라는 이름의 제네릭 타입 변수를 생성합니다.
T = TypeVar('T')

# 이 함수는 T 타입의 요소를 담은 리스트를 받아, T 타입의 요소를 반환합니다.
# 어떤 타입이든 리스트로 받으면, 그 타입의 요소를 그대로 반환함을 보장합니다.
def get_first_item(items: List[T]) -> T:
    return items[0]

# --- 사용 예시 ---
int_list = [1, 2, 3]
str_list = ["a", "b", "c"]

first_int = get_first_item(int_list)  # mypy는 first_int를 'int' 타입으로 추론
first_str = get_first_item(str_list)  # mypy는 first_str를 'str' 타입으로 추론

print(f"첫 번째 정수: {first_int}")
# get_first_item([True, False]) -> mypy는 반환 타입을 'bool'로 추론
```

### 제네릭 클래스: `Generic`

`typing.Generic`을 상속받아 제네릭 클래스를 만들 수 있습니다.

```python
from typing import TypeVar, Generic, List

T = TypeVar('T')

# Generic[T]를 상속받아 Stack 클래스를 제네릭 클래스로 만듭니다.
class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: List[T] = []  # 내부 아이템 리스트도 T 타입을 따릅니다.

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

# --- 사용 예시 ---
# int 타입만 담을 수 있는 스택 생성
int_stack = Stack[int]()
int_stack.push(123)
# int_stack.push("abc")  # 정적 타입 검사기가 여기서 오류를 감지합니다.

# str 타입만 담을 수 있는 스택 생성
str_stack = Stack[str]()
str_stack.push("hello")
value = str_stack.pop() # mypy는 value를 'str' 타입으로 추론
```
이처럼 제네릭을 사용하면, 타입 힌트를 통해 더 안정적이고 명확한 코드를 작성할 수 있습니다.
